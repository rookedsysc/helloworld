# Java AutoConfiguredOpenTelemetrySdk로 trace 전파와 커스텀 ID 다루기

## 개요

`AutoConfiguredOpenTelemetrySdk + 환경 변수`를 써도 다음은 모두 가능합니다.

1. 들어오는 요청의 `traceparent`를 이어받아 같은 trace를 계속 사용하기
2. `X-Transaction-Id` 같은 비즈니스 ID를 span/log에 같이 기록하기
3. `X-Correlation-Id` 같은 커스텀 헤더를 OpenTelemetry context로 연결하기

핵심은 `AutoConfiguredOpenTelemetrySdk`가 "SDK 초기화 방식"일 뿐이라는 점입니다. 전파와 상관관계는 `ContextPropagators`, `Context`, `Span`, `Baggage`, logging 연동으로 처리합니다.

## 전제 코드

아래 예시는 모두 이 초기화 코드를 공통으로 사용합니다.

### `TelemetryBootstrap.java`

```java
package example.otel;

import io.opentelemetry.api.OpenTelemetry;
import io.opentelemetry.instrumentation.logback.appender.v1_0.OpenTelemetryAppender;
import io.opentelemetry.sdk.OpenTelemetrySdk;
import io.opentelemetry.sdk.autoconfigure.AutoConfiguredOpenTelemetrySdk;

public final class TelemetryBootstrap {

  private TelemetryBootstrap() {
  }

  public static OpenTelemetry init() {
    OpenTelemetrySdk sdk = AutoConfiguredOpenTelemetrySdk.initialize().getOpenTelemetrySdk();
    OpenTelemetryAppender.install(sdk);
    return sdk;
  }
}
```

### 환경 변수 예시

```bash
export OTEL_SERVICE_NAME="payment-api"
export OTEL_TRACES_EXPORTER="otlp"
export OTEL_LOGS_EXPORTER="otlp"
export OTEL_METRICS_EXPORTER="none"
```

## 1. `traceparent`를 받아 같은 traceId를 이어가는 예시

### 핵심 설명

이 방식에서는 `traceId`를 직접 문자열로 세팅하지 않습니다.

- 요청 헤더의 `traceparent`를 `extract()`로 읽고
- 그 `Context`를 현재 스코프에 올린 뒤
- 새 span을 만들면 부모 trace를 이어받습니다.

Spring MVC / WebFlux / Java agent / Spring starter를 쓰면 보통 이 과정은 자동입니다. 아래 코드는 원리를 명확하게 보여주기 위한 수동 예시입니다.

### `IncomingTraceFilter.java`

```java
package example.otel;

import io.opentelemetry.api.OpenTelemetry;
import io.opentelemetry.api.trace.Span;
import io.opentelemetry.api.trace.SpanKind;
import io.opentelemetry.api.trace.Tracer;
import io.opentelemetry.context.Context;
import io.opentelemetry.context.Scope;
import io.opentelemetry.context.propagation.TextMapGetter;
import jakarta.servlet.FilterChain;
import jakarta.servlet.ServletException;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import java.io.IOException;
import java.util.Collections;
import org.springframework.web.filter.OncePerRequestFilter;

public class IncomingTraceFilter extends OncePerRequestFilter {

  private static final TextMapGetter<HttpServletRequest> GETTER = new TextMapGetter<>() {
    @Override
    public Iterable<String> keys(HttpServletRequest carrier) {
      return Collections.list(carrier.getHeaderNames());
    }

    @Override
    public String get(HttpServletRequest carrier, String key) {
      return carrier.getHeader(key);
    }
  };

  private final OpenTelemetry openTelemetry;
  private final Tracer tracer;

  public IncomingTraceFilter(OpenTelemetry openTelemetry) {
    this.openTelemetry = openTelemetry;
    this.tracer = openTelemetry.getTracer("example.incoming-filter", "1.0.0");
  }

  @Override
  protected void doFilterInternal(
      HttpServletRequest request,
      HttpServletResponse response,
      FilterChain filterChain) throws ServletException, IOException {

    // 들어온 traceparent/baggage에서 부모 context를 추출한다.
    Context extracted = openTelemetry.getPropagators()
        .getTextMapPropagator()
        .extract(Context.current(), request, GETTER);

    Span serverSpan = tracer.spanBuilder(request.getMethod() + " " + request.getRequestURI())
        .setParent(extracted)
        .setSpanKind(SpanKind.SERVER)
        .startSpan();

    try (Scope scope = serverSpan.makeCurrent()) {
      filterChain.doFilter(request, response);
    } finally {
      serverSpan.end();
    }
  }
}
```

### 동작 예시

외부 시스템이 아래 헤더로 호출하면:

```http
traceparent: 00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01
```

위 필터에서 만든 `serverSpan`은 같은 `traceId=4bf92f3577b34da6a3ce929d0e0e4736` 아래에 생성됩니다.

## 2. `X-Transaction-Id`를 span과 log에 같이 남기는 예시

### 핵심 설명

`transactionId`는 표준 OTel trace ID가 아니라 비즈니스 식별자입니다. 그래서 가장 안전한 방식은:

- 요청 헤더에서 읽고
- 현재 span attribute에 넣고
- 로그에도 같이 남기는 것

입니다.

### `TransactionIdFilter.java`

```java
package example.otel;

import io.opentelemetry.api.trace.Span;
import jakarta.servlet.FilterChain;
import jakarta.servlet.ServletException;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import java.io.IOException;
import org.slf4j.MDC;
import org.springframework.web.filter.OncePerRequestFilter;

public class TransactionIdFilter extends OncePerRequestFilter {

  public static final String HEADER_NAME = "X-Transaction-Id";

  @Override
  protected void doFilterInternal(
      HttpServletRequest request,
      HttpServletResponse response,
      FilterChain filterChain) throws ServletException, IOException {

    String transactionId = request.getHeader(HEADER_NAME);

    if (transactionId != null && !transactionId.isBlank()) {
      Span.current().setAttribute("app.transaction_id", transactionId);
      MDC.put("transactionId", transactionId);
    }

    try {
      filterChain.doFilter(request, response);
    } finally {
      MDC.remove("transactionId");
    }
  }
}
```

### `PaymentController.java`

```java
package example.otel;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController

  private static final Logger log = LoggerFactory.getLogger(PaymentController.class);

  @GetMapping("/payments/approve")
  public String approve() {
    log.info("approving payment");
    return "ok";
  }

```

### `logback.xml`

```xml
<?xml version="1.0" encoding="UTF-8"?>
<configuration>
  <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
    <encoder>
      <pattern>%d{HH:mm:ss.SSS} trace_id=%X{trace_id} span_id=%X{span_id} transactionId=%X{transactionId} %-5level %logger{36} - %msg%n</pattern>
    </encoder>
  </appender>

  <appender name="OTEL_MDC" class="io.opentelemetry.instrumentation.logback.mdc.v1_0.OpenTelemetryAppender">
    <appender-ref ref="CONSOLE"/>
  </appender>

  <root level="INFO">
    <appender-ref ref="OTEL_MDC"/>
  </root>
</configuration>
```

### 효과

- Tempo trace에는 `app.transaction_id` attribute가 남습니다.
- Loki log에는 `transactionId`, `trace_id`, `span_id`가 같이 남습니다.
- 따라서 Grafana에서 transactionId로 로그를 찾고, trace_id로 trace까지 연결할 수 있습니다.

## 3. 커스텀 헤더를 OpenTelemetry context로 매핑하는 고급 예시

### 핵심 설명

만약 외부 시스템이 `traceparent` 대신 `X-Correlation-Id` 같은 헤더만 보내고 있다면, 그 값을 OTel의 표준 `traceId`로 강제 변환하는 것은 권장되지 않습니다.

대신 추천되는 방식은:

- 커스텀 헤더를 `Baggage`나 custom `ContextKey`로 넣고
- span attribute / log field로 복사해서 사용하기

입니다.

아래 예시는 `X-Correlation-Id`를 baggage로 주고받는 custom propagator 예시입니다.

### `CorrelationIdPropagator.java`

```java
package example.otel;

import io.opentelemetry.api.baggage.Baggage;
import io.opentelemetry.api.baggage.BaggageBuilder;
import io.opentelemetry.context.Context;
import io.opentelemetry.context.propagation.TextMapGetter;
import io.opentelemetry.context.propagation.TextMapPropagator;
import io.opentelemetry.context.propagation.TextMapSetter;
import java.util.Collection;
import java.util.List;

public class CorrelationIdPropagator implements TextMapPropagator {

  public static final String HEADER_NAME = "X-Correlation-Id";
  public static final String BAGGAGE_KEY = "correlation.id";

  @Override
  public Collection<String> fields() {
    return List.of(HEADER_NAME);
  }

  @Override
  public <C> void inject(Context context, C carrier, TextMapSetter<C> setter) {
    String correlationId = Baggage.fromContext(context).getEntryValue(BAGGAGE_KEY);
    if (correlationId != null && !correlationId.isBlank()) {
      setter.set(carrier, HEADER_NAME, correlationId);
    }
  }

  @Override
  public <C> Context extract(Context context, C carrier, TextMapGetter<C> getter) {
    String correlationId = getter.get(carrier, HEADER_NAME);
    if (correlationId == null || correlationId.isBlank()) {
      return context;
    }

    BaggageBuilder builder = Baggage.fromContext(context).toBuilder();
    builder.put(BAGGAGE_KEY, correlationId);
    return context.with(builder.build());
  }
}
```

### `TelemetryBootstrap.java`를 커스터마이즈한 예시

```java
package example.otel;

import io.opentelemetry.api.OpenTelemetry;
import io.opentelemetry.context.propagation.TextMapPropagator;
import io.opentelemetry.instrumentation.logback.appender.v1_0.OpenTelemetryAppender;
import io.opentelemetry.sdk.OpenTelemetrySdk;
import io.opentelemetry.sdk.autoconfigure.AutoConfiguredOpenTelemetrySdk;

public final class TelemetryBootstrap {

  private TelemetryBootstrap() {
  }

  public static OpenTelemetry init() {
    OpenTelemetrySdk sdk = AutoConfiguredOpenTelemetrySdk.builder()
        .addPropagatorCustomizer((existing, config) -> TextMapPropagator.composite(
            existing,
            new CorrelationIdPropagator()))
        .build()
        .getOpenTelemetrySdk();

    OpenTelemetryAppender.install(sdk);
    return sdk;
  }
}
```

### 현재 baggage 값을 span/log에 반영하는 예시

```java
package example.otel;

import io.opentelemetry.api.baggage.Baggage;
import io.opentelemetry.api.trace.Span;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

public class CorrelationLoggingService {

  private static final Logger log = LoggerFactory.getLogger(CorrelationLoggingService.class);

  public void process() {
    String correlationId = Baggage.current().getEntryValue(CorrelationIdPropagator.BAGGAGE_KEY);

    if (correlationId != null) {
      Span.current().setAttribute("app.correlation_id", correlationId);
    }

    log.info("processing with correlationId={}", correlationId);
  }
}
```

### 언제 이 방식을 써야 하나

- 외부 시스템이 아직 `traceparent`를 보내지 않음
- 사내 표준 header가 이미 `X-Correlation-Id`로 굳어 있음
- 해당 값을 traceId로 바꾸는 대신, 관측 상관관계용 보조 context로 유지하고 싶음

## 권장 방식 정리

### 1. 가장 먼저 선택할 것

가능하면 외부 시스템도 `traceparent`를 보내게 맞추는 것이 가장 좋습니다.

### 2. 비즈니스 ID는 traceId로 강제하지 말 것

`transactionId`, `orderId`, `correlationId`는 span attribute / baggage / log field로 두는 편이 안전합니다.

### 3. autoconfigure를 쓰더라도 충분히 확장 가능함

`AutoConfiguredOpenTelemetrySdk.builder()`를 쓰면 propagator customizer 같은 확장이 가능합니다.

## 요약

`AutoConfiguredOpenTelemetrySdk + 환경 변수`를 써도 아래는 전부 가능합니다.

1. `traceparent`를 받아 같은 traceId를 이어가기
2. `transactionId`를 span/log에 같이 남기기
3. 커스텀 헤더를 baggage/context로 전파하기

즉, autoconfigure는 단순화된 초기화 방식일 뿐이고, 전파와 상관관계 제어는 충분히 확장 가능합니다.
